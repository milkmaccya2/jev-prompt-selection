# Clef 補足の追加: Worker から `env.AI` で呼んだときの判定時間(計画)

作成: 2026-10-11(測定の前に保存)。[PLAN.md](PLAN.md) の測定(端末から REST で呼んだもの、2026-10-11 21:09 JST)の追加です。

## 問い

Worker の中から Workers AI バインディング(`env.AI.run`)で Clef / Clef-flash を呼ぶと、判定時間はどれくらいか。端末から REST で呼んだときとどれだけ違うか。

## 方法

- 測定専用の一時的な Worker `clef-latency-probe`(`probe/clef-worker/`)を作ります。公開中のデモ(`jev-prompt-selection`)は変えません。測定が終わったら削除します。
- Worker は1回のリクエストで `env.AI.run` を1回だけ呼びます。合言葉のヘッダー(`PROBE_KEY`、シークレット)がないリクエストは断ります。
- 端末の実行スクリプトは REST の測定と同じです: test 100件・12候補、ウォームアップ3発話、各件で2モデルの順番を種 `20261011` で並べ替え、1件ずつ順番に、再試行なし、30秒でタイムアウト。本文(`model`・`state`・`questions`)も REST の測定と同じです。
- 記録する時間は2つです。
  - **主: Worker の中の時間**: `env.AI.run` を呼ぶ直前から結果が返るまで(`Date.now()`)。
  - 参考: 端末から Worker までの往復を含めた時間(REST の測定と同じ測り方)。
- Worker が動いたデータセンター(`request.cf.colo`)も記録します。
- 正解率・確信度も集計しますが、主な目的は判定時間です。REST の測定の正解率を置き換えません。
- 失敗は記録し、不正解として採点します。予算で止まった、途中で終わった、ハッシュが変わった実行は集計しません。

## 費用

REST の測定と同じ見込み(上限 $0.20)。Worker の実行自体は無料枠の範囲です。

## 注意として書くこと

- REST の測定とも v4 本編とも別の実行です。
- Worker の中の時間は、端末からの往復を含まないので、v4 の4構成(端末から測った時間)とはそのままでは比べられません。
- Workers の時計は I/O の前後でしか進まないので、`env.AI.run` の前後の差は測れますが、ミリ秒より細かい値は出ません。
