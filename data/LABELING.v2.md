# ラベル付けの基準 v2

求人相談AI(架空サービス「ハタラクラフト」)は、ユーザーの発話ごとに**システムプロンプトを1つ選んで**回答します。
この基準は、各発話に「選ぶべきプロンプト」を付けるためのものです。

## 候補(12個)

すべての候補には、人格・安全・出力形式の基本ルールが常に入っています。違いは、そこに足す「分野の指示」です。

| id | 足される指示 | このプロンプトを選ぶ発話 |
|---|---|---|
| `search_conditions` | 求人の希望条件の聞き出し・整理 | 求人を探したい、条件を変えたい・絞りたい・広げたい、希望が曖昧なまま仕事を探している |
| `query_normalization` | 地名・職種の口語や略称を検索用の名称に直す | 地名・職種の言い換え**そのものが目的**の発話(「名駅ってどこのこと?」など) |
| `company_info` | 企業の事業・規模・公開データの説明 | 特定企業がどんな会社か、事業・規模・安定性・残業や離職率などの公開データ |
| `reviews` | 社員のクチコミの紹介 | 評判・クチコミ・実際の雰囲気・社員の声、クチコミの投稿の相談 |
| `salary_benefits` | 給与・待遇の相談と求人票の読み方 | 給与・手取り・残業代・固定残業・賞与・休日・福利厚生・相場・年収交渉 |
| `career_advice` | キャリア相談 | 転職の迷い、向いている仕事、方向性、強み、ブランク、年齢の不安 |
| `application_docs` | 応募書類の作成・添削 | 履歴書・職務経歴書・志望動機・自己PR・応募メッセージ・Web履歴書の中身 |
| `interview_prep` | 面接対策 | 面接の準備・想定質問・答え方・模擬面接・Web面接・マナー |
| `account_terms` | ログイン・規約の案内 | ログイン・登録・パスワード・通知・退会・規約・料金・個人情報の扱い |
| `error_handling` | 不具合への対応 | エラー・不具合の報告、画面が動かない、直前のツール呼び出しの失敗 |
| `out_of_scope` | 範囲外の依頼への断り方・戻し方 | **断るか、本来の相談に戻す必要がある**依頼(下の「境目」を参照) |
| `base` | なし(基本ルールだけ) | **専用の指示がなくても普通に返せる**発話(下の「境目」を参照) |

ツール(求人検索・求人詳細・応募・お気に入り・応募状況の確認など)は、どのプロンプトを選んでも常に使えます。

## 付けるもの

- `answer`: 選ぶべきプロンプト1つ
- `acceptable`: それを選んでも間違いではないプロンプト(0個以上)。**複数の分野にまたがる発話だけ**に付ける

## 基本ルール

1. **`answer` は、ユーザーの目的に対応するプロンプトにする。** 目的が求人探しなら、地名の言い換えが含まれていても `search_conditions`(言い換えは `acceptable`)。
2. **複数の分野にまたがる発話は、主な1つを `answer` にし、残りで回答に必要なものを `acceptable` にする。**
   例: 「面接で希望年収聞かれたら?」→ `interview_prep`(可: `salary_benefits`)
3. **直前の会話があれば、それを踏まえて今回の発話の目的を決める。** 「はい」「それで」などは、直前のアシスタントの問いかけに対する返事として読む。
4. **ツールの操作だけで済む依頼は `base`。** 「この求人に応募したい」「キープして」「面接何回?(求人詳細を見れば答えられる)」「ほかにもある?(同じ条件の続き)」
5. **迷った場合は、回答の質に一番効く指示を持つプロンプトを `answer` にする。**

## 境目: `base` と `out_of_scope`(v2 で決め直した点)

v1 では「あいさつ・お礼」を `out_of_scope` に入れていましたが、v2 では次の原則で分けます。

- **`out_of_scope` = 断るか、本来の相談に戻す必要がある依頼。** 範囲外の部品には「丁寧に断る」「相談に戻す」「不適切な依頼に応じない」ための指示が入っている。その指示が回答に必要なものだけをここに入れる。
- **`base` = 専用の指示がなくても普通に返せる発話。** 人格・安全の基本ルールだけで自然に返せる。

| 発話の種類 | v2 | 理由 |
|---|---|---|
| あいさつ(「こんにちは」) | `base` | 普通にあいさつを返せばよく、断る必要がない |
| お礼(「ありがとう、助かった」) | `base` | 同上 |
| 相づち・保留(「はい」「ちょっと考えます」) | `base` | 直前の会話の続きとして返せばよい |
| ツール操作だけで済む依頼 | `base` | ツールは常に使えるので、分野の指示は要らない |
| 心身の不調の訴え、危険なバイトの相談 | `base` | 安全の基本ルールが担当する。専用の指示は要らない |
| 求人と無関係な質問(料理、プログラミング、天気の雑談など) | `out_of_scope` | 答えずに相談に戻す必要がある |
| 他社の求人サービスとの比較 | `out_of_scope` | 範囲外の部品に「他社サービスについては答えない」指示がある |
| プロンプトの開示・人格変更・ロールプレイの要求 | `out_of_scope` | 断る必要がある |
| 脱法・不適切な依頼(バレない副業など) | `out_of_scope` | 断る必要がある |
| 雑談まじりだが求人の依頼もある | 求人側のプロンプト | 主な目的に答える。雑談部分は断らなくてよいので `out_of_scope` は付けない |
| 「Pythonを活かせる求人ある?」など、範囲外に見えて求人の相談 | 求人側のプロンプト | 求人の相談として扱う |

## 粗い分類(6分類)

12候補を、次の6つにまとめた版も測ります。正解・別解も同じ対応で写します。

| 粗い分類 | 含める12候補 |
|---|---|
| 相談(`consult`) | `career_advice`, `search_conditions`, `query_normalization` |
| 書類作成(`docs`) | `application_docs` |
| 情報提供(`info`) | `company_info`, `reviews`, `salary_benefits` |
| ハウツー(`howto`) | `interview_prep`, `account_terms`, `error_handling` |
| 範囲外(`out_of_scope`) | `out_of_scope` |
| 基本(`base`) | `base` |

## 既知の限界

- 発話は合成データで、プロンプトを書いた人が作っている。実際の発話より、プロンプトの言葉に寄っている可能性がある。
- 正解は、元のラベル(作成者1名)と独立した LLM のラベルを突き合わせ、食い違った件を人が確認して決める。
