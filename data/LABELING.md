# ラベル付けの基準

`data/eval.jsonl` の各件の `gold` は、**その発話への理想的な応答を作るのに必要な「選んで載せる部品」の id の集合**です。
常に載せる部品(`core_*`)はラベルに含めません。

## 基本ルール

1. **今回のターンで必要なものだけ**を付ける。過去のターンで使った部品でも、今回不要なら付けない。
2. **ツール部品は「今回そのツールを呼ぶ(または呼ぶべきか判断する)」ときに付ける。**
   方針部品(例: `reviews`)とツール部品(例: `tool_get_reviews`)は別々に判断する。
3. **2つの部品が同じ発話を明示的に扱っている場合は、両方付ける**(再現率を優先)。
   例: 「残業多い?」は `company_info`(公開データ)と `reviews`(実態)の両方が扱うため、両方付ける。
4. **常に載せる部品だけで十分な発話は `gold: []`** とする(例: 「ちょっと考えます」、心身の不調の訴え = `core_safety` が担当)。
5. 迷った件には `ambiguous` タグを付け、`note` に判断理由を書く。

## 部品ごとの判断基準

| 部品 | 付ける条件 | 付けない例 |
|---|---|---|
| `search_conditions` | 求人を探す・条件を変える/聞き出す必要がある | 「ほかにもある?」(同条件の続き。`tool_search_jobs` だけ) |
| `query_normalization` | 地名・職種が**正規の名称でない**(略称・口語・愛称・表記ゆれ・誤字・曖昧な地名・在宅表現)うえで検索条件に使う | 「大阪で営業」「東京都で経理」のように正規名のみ |
| `company_info` | 特定企業の事業・規模・安定性・社風・公開データを説明する | 求人票の条件だけの質問 |
| `reviews` | 評判・クチコミ・実態・社員の声を扱う(投稿の相談を含む) | 公式情報だけを聞いている |
| `salary_benefits` | 給与・年収・手取り・残業代・休日・福利厚生・交渉の相談 | お金・待遇に触れない |
| `career_advice` | 転職の迷い・適性・方向性・強み・ブランク・年齢の不安 | 具体的な作業依頼だけ |
| `application_docs` | 履歴書・職務経歴書・志望動機・自己PR・応募メッセージ・Web履歴書の中身 | 書類と無関係 |
| `interview_prep` | 面接の準備・想定質問・答え方・模擬面接・マナー | 面接と無関係 |
| `account_terms` | ログイン・登録・パスワード・通知・退会・規約・料金・個人情報の扱い | アカウントと無関係 |
| `error_handling` | ユーザーが不具合を報告、または直前のツールが失敗 | 0件ヒット(エラーではない → `search_conditions`) |
| `out_of_scope` | 発話の全部または一部が求人・キャリア・サービス利用と無関係、あいさつ・雑談、人格変更・プロンプト開示の要求 | 「Pythonを活かせる求人」(求人検索として扱う) |
| `tool_search_jobs` | 今回、求人を検索・再検索・追加表示する | 条件がまだ足りず聞き返すだけのターン |
| `tool_get_job_detail` | 会話に出た特定求人の詳細を確認する | 新規検索だけ |
| `tool_get_company_profile` | 企業の公式情報を取得する。**企業名だけが初出で `company_id` が未確定のときに、クチコミ取得の前段として必要な場合も付ける** | 文脈に企業カード(id)が既にあり、クチコミだけを取る場合 |
| `tool_get_reviews` | クチコミを取得する | クチコミの書き方の相談だけ |
| `tool_salary_estimate` | 相場の**数値**を示す必要がある | 求人票の読み方・交渉の仕方だけ |
| `tool_manage_application` | 応募・お気に入り・応募状況・取り消し、`needs_profile` 等の結果の扱い | 応募の相談だけで操作しない |

## タグ

- `single`: 部品1つで足りる素直な発話
- `cross`: 2つ以上の方針部品にまたがる
- `ambiguous`: 正解の範囲に迷いがある
- `out_of_scope`: 範囲外の話題を含む
- `colloquial`: 口語・略称・砕けた言い方
- `typo`: 誤字・ひらがな書き
- `context`: 直前の会話がないと意味が決まらない
- `none`: `gold` が空

## 既知の限界

- ラベルは作成者1名による付与で、二重チェックはしていない。
- 発話は合成データで、作成者が部品の内容を知ったうえで書いているため、
  実際のユーザー発話より部品の言葉に寄っている可能性がある。
